# Регистрация

Структура фронтенда сохранена: `App.tsx` содержит маршруты, `feature` — страницы
и компоненты сайта, `assets` — ресурсы, `library/keycloak` — адаптер авторизации
и серверную тему `solyanka`. `main.tsx` подключает ReactKeycloakProvider с
`login-required`. Форма регистрации поэтому является страницей Keycloak, а не
новым React-маршрутом. Docker Compose уже монтирует эту тему.

На странице входа используется штатная ссылка регистрации Keycloak. Четыре поля
отправляются на `url.registrationAction`; сессионные параметры формирует сервер.
Email и логин обязательны, логин содержит 3–255 символов (существующее правило realm).
Пароль: минимум 8 символов, хотя бы одна латинская буква любого регистра и цифра.
Оба пароля скрыты. Политика продублирована в realm, уникальность проверяет Keycloak.
Дубликаты логина/email имеют одинаковое сообщение.

Ошибки полей возвращаются в действующую форму, пароль хранится только в её памяти,
без записи в браузерные хранилища. При сетевой ошибке/HTTP 5xx данные остаются.
Успешный redirect после POST запускает возвращение на главную исходного клиента;
KeycloakProvider завершает вход через созданную SSO-сессию. Уведомление показывается
после успешной инициализации авторизации. Исходный адрес клиента сохраняется
в sessionStorage на странице входа, пароли туда не записываются.

## Настройка

Тестовая учётная запись при новом импорте: `test` / `Test12345`.
Старый пароль `test` не соответствует политике регистрации и блокирует импорт.

Для нового realm достаточно существующего `docker compose up`. Для уже созданного
realm импорт при старте не обновляет настройки: примените Password policy
`length(8) and digits(1) and regexPattern(.*[a-zA-Z].*)` через Admin Console.
Убедитесь, что Registration включена, Duplicate emails выключена, тема входа —
`solyanka`, обязательных действий после регистрации нет. При разработке отключите
кеш темы либо перезапустите Keycloak. Адрес `keycloak` должен разрешаться в браузере.

## Проверки

Из `frontend`: `node --test src/library/keycloak/registration.test.mjs`.
Тесты правил используют встроенный runner Node и не требуют npm install.

Ручной интеграционный сценарий на Keycloak 26:
1. Открыть сайт без сессии, перейти к регистрации, проверить макет на 1920×1080 и 375×812.
2. Отправить пустую форму, неправильный Email, короткий пароль, пароль без букв/
   цифр, несовпадающее подтверждение: ошибки должны объяснять причину.
3. Создать уникальный аккаунт: главная, активная сессия, уведомление об успехе.
4. Выйти и повторить регистрацию с занятым логином, затем с занятым email:
   «Пользователь с таким логином или email уже существует».
5. Отключить сеть перед отправкой: уведомление об ошибке, все поля сохранены.
6. Проверить ссылку «Уже есть аккаунт? Войти».

Автотесты правил не заменяют проверку FreeMarker и полного OIDC-потока на сервере.
Ревью, закрытие задачи и merge выполняются через принятый в команде процесс.
