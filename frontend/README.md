# Солянка — Frontend

Главная страница кулинарного сервиса «Солянка». Она знакомит пользователя с проектом, даёт доступ к разделам
рецептов, профилю и избранному. Доступ к приложению защищён Keycloak: при отсутствии активной сессии провайдер
перенаправляет пользователя на форму входа до показа главной страницы.

## Стек
React, TypeScript, Vite

## Запуск
1. `npm install`
2. `npm run dev`

Для локального входа должен быть доступен realm `solyanka` в Keycloak.

Тестовая учётная запись из локального realm: логин `test`, пароль `Test1234`. Она предназначена только для
командной разработки; email `test@test` уже отмечен как подтверждённый, обязательных действий при входе нет.

## Скрипты
- `npm run dev` — запуск в режиме разработки;
- `npm run build` — проверка TypeScript и production-сборка;
- `npm run lint` — статический анализ;
- `npm test` — компонентные тесты главной страницы и состояния авторизации.

## Структура

Файлы сгруппированы по назначению. Компоненты, стили и ассеты главной страницы
лежат рядом; настройка авторизации, её тесты и тема Keycloak собраны в одном месте.

```text
src/
├── main.tsx                       # запуск React и подключение провайдера Keycloak
├── app/
│   ├── App.tsx                    # композиция приложения и состояние загрузки
│   ├── App.test.tsx
│   └── global.css                 # общие переменные, сброс стилей, доступность
├── pages/home/
│   ├── HomePage.tsx
│   ├── HomePage.test.tsx
│   ├── home.css                   # оформление страницы и её компонентов
│   ├── components/                # Header и Footer
│   └── assets/                    # картинки и декоративный шрифт главной
├── library/keycloak/
│   ├── client.ts                  # клиент и параметры инициализации Keycloak
│   ├── client.test.ts
│   ├── RegistrationNotice.tsx     # уведомление после регистрации и очистка URL
│   ├── auth.css                   # загрузка авторизации и уведомление
│   ├── registration.test.js
│   └── solyanka/login/            # тема, которую обслуживает сервер Keycloak
│       ├── register.ftl           # форма регистрации
│       ├── theme.properties
│       ├── messages/              # тексты интерфейса и ошибок
│       └── resources/             # CSS, JS, изображения и шрифты темы
└── test/setup.ts                  # общая настройка тестов
```

Новую страницу добавляйте отдельной папкой в `pages`, вместе с её стилями и тестами.
Код входа и регистрации меняйте в `library/keycloak`. Тема `solyanka/login` работает
в Keycloak отдельно от React; её ресурсы имеют структуру, которую ожидает Keycloak.
Путь `src/library/keycloak/solyanka` сохранён для существующего Docker volume.

## Регистрация

Регистрация выполняется сервером Keycloak, тема `solyanka` содержит `register.ftl`,
стили и браузерную проверку полей. На странице входа стандартная ссылка Keycloak
«Нет аккаунта? Зарегистрироваться» ведёт в registration flow; обратная ссылка —
«Уже есть аккаунт? Войти». Docker уже монтирует тему из `frontend`, изменения Compose не нужны.
Тема поставляется отдельно от Vite-сборки; после изменения файлов может потребоваться
сброс кеша темы или перезапуск Keycloak.

Форма содержит отдельные обязательные логин и Email, пароль и подтверждение с маской.
Ошибки полей на формах входа и регистрации используют общий стиль: цвет, шрифт,
размер и отступ под полем; невалидные поля выделяются одинаковой красной рамкой.
Серверные ошибки полей не дублируются общим уведомлением над формой.
Минимум пароля — 8 символов, хотя бы одна буква (включая кириллицу) и цифра `0–9`.
Проверяются совпадение паролей и Email с доменной зоной. Для логина учитывается
существующее ограничение realm: минимум 3 символа. Серверные ошибки уникальности
логина и Email локализованы одинаково: «Пользователь с таким логином или email уже существует».

Скрипт темы запоминает в `sessionStorage` только адрес возврата из OIDC-запроса.
Пароли и остальные значения формы не записываются в хранилища и логи.
POST отправляется на `url.registrationAction` Keycloak. При ответе с ошибками
обновляются сообщения и адрес повторной отправки, значения всех полей остаются в DOM.
Сетевые ошибки и HTTP 5xx показывают уведомление и позволяют повторить отправку;
на время запроса кнопка блокируется от двойного нажатия.

Перенаправление после POST обрабатывается с `redirect: manual`: браузер возвращается
на главную приложения, где новый OIDC-запрос использует созданную Keycloak SSO-сессию.
Авторизационный callback не загружается через fetch. После аутентификации приложение
показывает уведомление об успехе и убирает служебный параметр `registration` из URL.
При дополнительных required actions их выполнение остаётся за Keycloak.
Если JavaScript или sessionStorage недоступны либо форма открыта без исходного OIDC-запроса,
работает обычная отправка формы Keycloak; в этом режиме сохранение паролей после ошибки
и уведомление приложения об успешной регистрации не гарантируются.

### Обязательная настройка сервера

В текущем `docker/solyanka-realm.json` уже включены `registrationAllowed`, отдельный
логин и уникальный Email; профиль содержит только username и email. Добавлена серверная
политика `length(8) and regexPattern((?s)^(?=.*\p{L})(?=.*[0-9]).*$)`.
При первом импорте realm она применяется автоматически. Для существующего realm
администратор должен установить те же значения в Authentication → Policies → Password policy:

- Minimum Length: `8`;
- Regular Expression: `(?s)^(?=.*\p{L})(?=.*[0-9]).*$`.

Изменён только экспорт realm; Compose и backend не изменялись. Для существующего
realm изменение import JSON само по себе не обновляет работающую конфигурацию —
политику необходимо применить также к активному realm. Не нужно удалять том с данными.

### Проверка регистрации

`npm test` проверяет обязательность, границы длины и состав пароля, совпадение,
формат Email, ошибки занятости обоих полей, сохранение значений при сетевых/серверных
ошибках, повторную отправку, блокировку двойного запроса, возврат после ответа Keycloak
и уведомление приложения после аутентификации. `npm run build` и `npm run lint`
проверяют сборку и статический анализ.

Для проверки на работающем Keycloak:

1. Открыть приложение, перейти со входа к регистрации и проверить адаптацию формы.
2. Проверить пустые поля, неправильный Email, слабый пароль и несовпадающее подтверждение.
3. Зарегистрировать новый уникальный аккаунт; проверить главную, активную сессию и уведомление.
4. Выйти, отдельно повторить занятый логин и занятый Email; проверить точный текст ошибки.
5. Отключить сеть при отправке: поля должны сохраниться, повторная отправка доступна.
6. Проверить прямую отправку слабого пароля без браузерной валидации:
   после настройки password policy сервер должен отказать.

Модульные тесты не запускают FreeMarker и Keycloak. Сквозные сценарии создания аккаунта,
SSO и отображение темы требуют отдельной проверки на работающем сервере.

## Главная страница

Страница повторяет desktop-макет 1440 × 1080 и адаптируется для узких экранов. Навигация содержит ссылки на
все рецепты, рецепты пользователя, избранное и профиль. Кнопка «Выйти» завершает Keycloak-сессию. Сердце
избранного окрашивается и делает оборот при наведении; при системной настройке `prefers-reduced-motion` анимации
отключаются.

Типографика макета: Valisca 96 px для декоративного заголовка, Brygada 1918 50 px для слогана и 24 px для основного текста,
Piazzolla Bold 20 px для навигации и Piazzolla Light 14 px для подвала. Все шрифты включаются в production-сборку
и не требуют обращения к внешнему CDN.
